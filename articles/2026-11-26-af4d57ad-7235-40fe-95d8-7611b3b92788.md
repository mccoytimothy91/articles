# 照片推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:af4d57ad-7235-40fe-95d8-7611b3b92788 -->

## 问题场景

照片状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/photo/stream', (msg) => {
  state.count += 1;
  document.querySelector('#photo-badge').textContent = state.count;
});
```

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

在迁移过程中，可以通过压测确认容量水位，避免资源被长期占用。

在跨团队协作时，建议在变更前留一份可回滚的快照，让新人上手时少走弯路。

遇到复杂链路时，优先保证失败时能快速定位原因，确保线上行为始终可控。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，使整体改动风险可控。

在迁移过程中，可以通过压测确认容量水位，便于横向对比不同方案的效果。

从长期维护角度看，优先保证失败时能快速定位原因，并同步给相关方知会。

在资源受限的环境下，建议在变更前留一份可回滚的快照，避免资源被长期占用。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从长期维护角度看，优先保证失败时能快速定位原因，并同步给相关方知会。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，保证每一步都可验证。
