# 薪资组件的行为用轻量 DOM 测试固定下来

<!-- content-workspace-job:77eeffec-b7f3-42be-ac89-0115363fbe12 -->

## 问题场景

薪资组件改一次样式就担心逻辑被带坏，手工点页面回归又太慢。

## 实现步骤

用 jsdom 造一个最小文档环境，把组件挂到容器上。

```javascript
import { JSDOM } from 'jsdom';
const dom = new JSDOM('<!doctype html><div id="root"></div>');
global.document = dom.window.document;
```

断言渲染出的文本、类名与事件后的状态变化，不断言具体标签结构。

```javascript
export function mount(html) {
  const root = document.querySelector('#root');
  root.innerHTML = html;
  return root;
}
```

每个用例结束后清空容器，避免上一个用例的节点影响选择器。

```javascript
const root = mount('<p class="salary">薪资</p>');
console.assert(root.querySelector('.salary').textContent === '薪资', 'render');
console.log('cases', 1, root.children.length, 12000);
```

## 注意事项

jsdom 不执行真实布局，依赖尺寸的断言要改用桩值；异步渲染要用 await 或宏任务等待后再断言。

如果数据量继续增长，需要评估对现有调用方的影响面，以便快速定位瓶颈。

对稳定性要求高的场景，需要评估对现有调用方的影响面，减少不必要的返工成本。

从排障效率看，应定期回顾相关监控指标，以便后续复盘有据可查。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，让新人上手时少走弯路。

从长期维护角度看，先把最小可复现的用例固定下来，让容量规划更有依据。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，并保留回滚开关以便快速恢复。

上线初期，要把异常路径和正常路径分别覆盖一遍，减少不必要的返工成本。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

在迁移过程中，可以通过压测确认容量水位，并保留回滚开关以便快速恢复。
