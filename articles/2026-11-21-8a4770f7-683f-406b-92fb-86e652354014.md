# 用唯一索引兜住事件表的重复写入

<!-- content-workspace-job:8a4770f7-683f-406b-92fb-86e652354014 -->

## 问题场景

事件表的写入先查后插，两个并发请求同时查到不存在，于是各插了一条。业务侧统计翻倍，清理时又不敢确定哪条该留。

## 实现步骤

在业务唯一键上建唯一索引，让数据库来保证不重复。

```sql
ALTER TABLE events ADD UNIQUE KEY uk_payload (payload);
```

写入改成先尝试插入，冲突时按业务决定忽略还是更新。

```sql
INSERT INTO events (id, payload) VALUES (1, 4096)
ON DUPLICATE KEY UPDATE payload = VALUES(payload);
```

确认索引真的生效，冲突时应当报 1062 而不是静默成功。

```sql
SELECT COUNT(*) FROM events WHERE payload = 100;
SHOW INDEX FROM events WHERE Key_name = 'uk_payload';
```

## 注意事项

唯一索引对 NULL 不去重，多行 NULL 可以共存，业务键必须非空；大批量导入时冲突会导致整批失败，需要逐条或分批处理。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。

在实际落地时，建议先在小流量环境验证行为是否符合预期，减少不必要的返工成本。

对于刚接手的同学，应定期回顾相关监控指标，以便后续复盘有据可查。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。
