# 总账页面弹层关闭后把焦点还给触发按钮

<!-- content-workspace-job:79608455-a97d-464a-b71a-cbde605dcc19 -->

## 问题场景

总账弹层关闭后焦点回到页面顶部，键盘操作者需要重新 Tab 十几次才能回到原来的位置。

## 实现步骤

打开弹层前记录 document.activeElement 作为返回目标。

```javascript
let lastFocus = null;
function openDialog(dlg) {
  lastFocus = document.activeElement;
  dlg.hidden = false;
  const first = dlg.querySelector('button, [href], input');
  if (first) first.focus();
}
```

弹层内做焦点循环，Tab 到末尾时回到第一个可聚焦元素。

```javascript
function closeDialog(dlg) {
  dlg.hidden = true;
  if (lastFocus && document.contains(lastFocus)) lastFocus.focus();
  lastFocus = null;
}
```

关闭时先恢复焦点，再移除弹层节点，顺序颠倒会丢失目标。

```javascript
const dlg = document.querySelector('#ledger-dialog');
openDialog(dlg);
closeDialog(dlg);
console.log('focus restored', document.activeElement.tagName, 880);
```

## 注意事项

display:none 的元素不可聚焦，恢复焦点前要确保元素仍可见；aria-modal 需要配合实际焦点限制才有效。

针对这类偶发问题，尽量把决策依据写进变更说明，避免资源被长期占用。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，便于横向对比不同方案的效果。

上线初期，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。

对稳定性要求高的场景，需要评估对现有调用方的影响面，并同步给相关方知会。

在多人协作的项目里，应当拆分步骤以便中途校验，让新人上手时少走弯路。

对稳定性要求高的场景，需要评估对现有调用方的影响面，确保线上行为始终可控。

从排障效率看，应定期回顾相关监控指标，降低同类问题再次发生的概率。

对稳定性要求高的场景，需要评估对现有调用方的影响面，减少不必要的返工成本。
