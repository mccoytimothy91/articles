# 电表组件的行为用轻量 DOM 测试固定下来

<!-- content-workspace-job:2313e076-716e-4749-8d6e-05f0c008d109 -->

## 问题场景

电表组件改一次样式就担心逻辑被带坏，手工点页面回归又太慢。

## 实现步骤

用 jsdom 造一个最小文档环境，把组件挂到容器上。

```javascript
import { JSDOM } from 'jsdom';
const dom = new JSDOM('<!doctype html><div id="root"></div>');
global.document = dom.window.document;
```

断言渲染出的文本、类名与事件后的状态变化，不断言具体标签结构。

```javascript
export function mount(html) {
  const root = document.querySelector('#root');
  root.innerHTML = html;
  return root;
}
```

每个用例结束后清空容器，避免上一个用例的节点影响选择器。

```javascript
const root = mount('<p class="meter">电表</p>');
console.assert(root.querySelector('.meter').textContent === '电表', 'render');
console.log('cases', 1, root.children.length, 3800);
```

## 注意事项

jsdom 不执行真实布局，依赖尺寸的断言要改用桩值；异步渲染要用 await 或宏任务等待后再断言。

上线初期，要把异常路径和正常路径分别覆盖一遍，以便快速定位瓶颈。

对于刚接手的同学，应定期回顾相关监控指标，防止出现隐性回归。

考虑到线上环境的差异，需要同时关注错误率与延迟两个指标，避免资源被长期占用。

在压测阶段，应把关键参数集中到配置中心统一管理，保证每一步都可验证。

从排障效率看，应定期回顾相关监控指标，让容量规划更有依据。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

从长期维护角度看，先把最小可复现的用例固定下来，防止出现隐性回归。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，并同步给相关方知会。

结合团队现状，可以通过日志补充上下文信息，保证每一步都可验证。

从排障效率看，应定期回顾相关监控指标，降低同类问题再次发生的概率。
