# 为退款表的amount统计建覆盖索引消除回表

<!-- content-workspace-job:fbcaf35d-b1d9-469d-9ca0-9258300e14a7 -->

## 问题场景

退款表的汇总查询只用到amount一列，却每次都回表几百万次，磁盘读放大严重，统计接口常年占着数据库三成负载。

## 实现步骤

确认查询涉及的列，全部放进联合索引，形成覆盖。

```sql
SELECT amount, COUNT(*) FROM refunds GROUP BY amount;
```

用 EXPLAIN 的 Extra 列确认出现 Using index，说明没有回表。

```sql
EXPLAIN SELECT amount FROM refunds WHERE amount > 75;
```

## 验证方法

Extra 显示 Using index 且 rows 与预估一致；接口耗时下降明显。

## 注意事项

覆盖索引会让索引变大，写入成本上升，更新频繁的表要权衡；SELECT * 一定会回表，统计查询应显式列出需要的列。

从长期维护角度看，先把最小可复现的用例固定下来，防止出现隐性回归。

对稳定性要求高的场景，需要评估对现有调用方的影响面，并同步给相关方知会。

在多人协作的项目里，应当拆分步骤以便中途校验，让新人上手时少走弯路。

对稳定性要求高的场景，需要评估对现有调用方的影响面，确保线上行为始终可控。

从排障效率看，应定期回顾相关监控指标，降低同类问题再次发生的概率。

对稳定性要求高的场景，需要评估对现有调用方的影响面，减少不必要的返工成本。

在资源受限的环境下，建议在变更前留一份可回滚的快照，避免资源被长期占用。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。
