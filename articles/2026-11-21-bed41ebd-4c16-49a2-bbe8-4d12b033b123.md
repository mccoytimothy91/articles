# 商品表按stock查询用不上索引的几种写法

<!-- content-workspace-job:bed41ebd-4c16-49a2-bbe8-4d12b033b123 -->

## 问题场景

商品表在stock上明明建了索引，按日期查还是全表扫描。把语句拿出来看，条件里对列做了函数运算，索引自然用不上。

## 实现步骤

定位问题：条件里出现函数、算术运算或类型不一致，索引都会失效。

```sql
EXPLAIN SELECT * FROM products WHERE DATE(created_at) = '2026-01-01';
```

把运算挪到常量侧，改成范围比较，索引就能正常命中。

```sql
SELECT * FROM products
WHERE created_at >= '2026-01-01' AND created_at < '2026-01-02';
```

用 EXPLAIN 确认 type 从 ALL 变成 range，rows 明显下降。

```sql
EXPLAIN SELECT * FROM products WHERE stock + 0 > 800;
CREATE INDEX idx_stock ON products (stock);
```

## 注意事项

字符串列与数字比较会触发隐式转换，同样失效；LIKE 只有前缀匹配能走索引；OR 连接不同列时优化器可能直接放弃索引。

在多人协作的项目里，应当拆分步骤以便中途校验，让新人上手时少走弯路。

从成本角度看，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从长期维护角度看，先把最小可复现的用例固定下来，降低同类问题再次发生的概率。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

在压测阶段，应把关键参数集中到配置中心统一管理，保证每一步都可验证。

从排障效率看，应定期回顾相关监控指标，让容量规划更有依据。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

从长期维护角度看，先把最小可复现的用例固定下来，防止出现隐性回归。
